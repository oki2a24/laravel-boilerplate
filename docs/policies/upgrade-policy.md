# アップグレード・ポリシー (Upgrade Policy)

このドキュメントは、プロジェクトにおける依存関係および Docker 環境のアップグレードに関する基本原則を定義します。AIエージェントはこの方針に従って作業を行い、ユーザーに提案を行います。

## 1. バージョン管理の方針 (Versioning Policy)

環境の安定性とセキュリティ・メンテナンスコストの最適化のため、以下の基準でバージョン管理を行います。

- **Dockerベースイメージ (Base Images):**
  **パッチバージョンまで厳密に固定**します（例: `php:8.4.21`）。これにより, 基盤となる実行環境の再現性を最大限に確保し、予期せぬ破壊的変更を防ぎます。
- **イメージ内パッケージ (Node.js, system libraries等):**
  **メジャーバージョンを固定し、マイナー・パッチはワイルドカードで許容**します（例: `nodejs=24.*`, `libicu-dev=76.*`）。これにより、パッチレベルのセキュリティアップデートやバグ修正を柔軟に受け入れられるようにし、メンテナンスの手間を軽減します。

## 2. 「逆引きピン留め」アプローチ (Reverse Engineering for Pinning)

アップグレード作業においては、以下の「リリースの解放 $\rightarrow$ 検証 $\rightarrow$ インスペクション $\rightarrow$ 固定」というプロセスを採用します。

1.  **制約の解放 (Release Constraints):**
    パッケージ（Node.js, system libraries等）のバージョン指定を完全に削除し、ビルド時にその時点での最新パッチが取得されるようにする。
2.  **検証 (Verification):**
    コンテナを起動し、アプリケーションと品質チェックが正常に動作することを確認する。
3.  **インスペクション & 固定 (Inspect & Pin):**
    実際にコンテナ内で動いている正確なバージョンを調査し、以下のポリシーに基づき `Dockerfile` を書き換える：
    *   **Dockerベースイメージ (PHP):** DockerHub 等を用いて最新の**パッチバージョン**を特定した上で、その値を厳密に固定する（例: `php:8.4.21-apache`）。
    *   **イメージ内パッケージ (Node.js, system libraries等):** 実行中の環境から取得した**メジャー・ワイルドカード形式**で固定する（例: `nodejs=24.*`, `libicu-dev=76.*`）ことで、パッチレベルの更新は許容しつつ安定性を確保する。

## 3. AIエージェントの検証義務 (Verification Duty)

エージェントが「完了」を報告したとしても、以下のプロセスを経て検証が行われない限り、タスクは完了とはみなされません。

1.  **実態確認 (Fact-Check):** エージェントは `cat` や `grep` 等を用いて、修正されたファイルの実際の記述内容を確認しなければなりません。エージェントの報告（テキスト）のみを信頼してはいけません。
2.  **意図の照合 (Intent Alignment Check):** 修正後のコードが、指示されたルール（例：「バージョン指定の完全な削除」か「ワイルドカードによる緩和」か）に正確に従っているかを厳密に検証しなければなりません。

## 4. AIによる自律的な自己修復ルール (AI Self-healing Rule)

アップグレード作業中、または依存関係の更新によってテストが失敗した場合, AIエージェントは以下のプロセスで「自律的な修正ループ」を実行することが許可されます。

1.  **原因特定:** テストエラーログやシステムログを分析し、不具合の根本原因（破壊的変更、互換性の欠如など）を特定する。
2.  **修正案の検討:** 依存関係の調整、コードの書き換え、または設定ファイルの修正を含む解決策を考案する。

## 5. 意思決定の原則

- **再現性の優先:** 手動での修正が必要な場合は、必ず `Dockerfile` や構成ファイルにその変更を反映させ、環境の再現性を維持すること。
- **ユーザーへの報告:** AIが自律的に解決できない問題（大幅なアーキテクチャ変更が必要な場合など）が発生した場合は, 直ちに作業を中断し、ユーザーに詳細なレポートを行うこと。
